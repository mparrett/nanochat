## Gotchas

- **Disk pressure (98 % used, ~22 GB free).** Pre-flight before any
  new pretrain. The bf16 run added ~1 GB peak; binary pretrain will
  be smaller (1-bit storage) but the optimizer state is fp32 and
  matches bf16's footprint. CLAUDE.md disk patterns apply:
  `--save-every=1000 --save-keep-last-n=2` caps a d6 pretrain at ~1 GB.

- **MPS hygiene.** Always `pgrep -lf python` and `pgrep -lf wandb`
  before launching any MPS run. Per CLAUDE.md, leftover workers can
  pin Metal context for hours.

- **`--model-tag` is mandatory for non-baseline runs.** Default
  `d<depth>` would clobber `d6_baseline_modern`. Today's bf16 run used
  `--model-tag=d6_bf16_validate`; any future binary run needs its own
  tag (suggested: `d6_binary_validate` etc).

- **Resume-after-crash works cleanly with `--resume-from-step=<N>`.**
  The bf16 first attempt crashed at step 2000; resume from step 1000
  produced a numerically equivalent trajectory (step-2000 val_bpb
  matched the original first run to within bf16 quantization noise).
  This pattern is reliable for any future crash-recovery scenario.

- **`tee -a` + `tail -f` produces stale events.** When I appended to
  the existing log file on resume, the persistent `tail -f` reattached
  and re-fired on the historical crash text in the file's tail. Solution
  for next time: use a fresh log file per resume (`/tmp/bf16_d6_validate_resume.log`)
  rather than appending.

- **Two LoRA monitors firing simultaneously** caused duplicate
  notifications late in the bf16 run. Always TaskStop the previous
  monitor before arming a fresh one for the same log.

- **`grep -E` warning trap in heredocs.** `tee -E` got confused with
  `rg -E` flag semantics in one Bash call. When piping to `rg`,
  remember `rg` uses different flag conventions (`-e` for pattern,
  no `-E`).

- **Branch is local-only.** Per `feedback_local_only.md` in memory and
  CLAUDE.md: never push, never open PRs in nanochat without explicit
  per-task approval. Two upstream-PR-worthy patches sit on this branch
  (the 2026-04-30 optim.py fix and today's flash_attention.py fix); they
  are NOT pushed.

  adopting. Doesn't apply to today's session (no Codex consultation

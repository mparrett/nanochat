## Run config

Same as first-pass except for `--total-batch-size` and `--sft-tag`
(deltas bold):

```
scripts/chat_sft.py --model-tag=d8_overnight --model-step=5000 \
  --sft-tag=d8_overnight_a2 \                       # was: d8_overnight
  --num-iterations=375 \
  --device-batch-size=8 --total-batch-size=65536 \  # was: 16384
  --eval-every=50 --eval-tokens=524288 \
  --chatcore-every=-1 \
  --save-every=100 --save-keep-last-n=2 \
  --grad-checkpoint \
  --run=d8_sft_overnight_a2
```

- **Total tokens trained:** 65,536 × 375 ≈ **24.6 M tokens** (**4× the
  first-pass 6.1 M**).
- **Grad-accum = 4** (vs first-pass's 1). Matches d6 canonical SFT.
- Same base ckpt, same 375 opt steps, same LR schedule (init_lr_frac=0.8,
  warmup_ratio=0, warmdown_ratio=0.5, final_lr_frac=0).
- Wall: **2 h 41 min** (4× the first-pass 48.5 min wall, as expected
  for 4× grad-accum on the same per-microbatch cost).
- Heavier paging than first-pass: 17.9 % sys-CPU share vs 10.5 %.
  Page faults 6.0× higher (377 k vs 63 k). Each step holds 4 microbatches
  of activations in the caching allocator, pushing memory pressure
  higher even with grad-checkpoint on.

## What this run answered (and didn't)

**Answered:**

- **The under-tokened-SFT hypothesis is correct.** 4× more effective
  tokens, same architecture, same base ckpt → val_bpb drops 0.15 bpb
  (19 % relative) and ChatCORE jumps 0.087 (116 % relative). Both
  shortfalls in the first-pass writeup's diagnosis are recipe-driven,
  not architecture-driven.
- **d8 is competitive with d6_stage2** at matched SFT recipe. d8 wins
  on val_bpb (0.622 vs 0.652); d6_stage2 slightly wins on ChatCORE
  (0.174 vs 0.162). Both are within `-x 100` noise on the ChatCORE
  side. The "d8 is worse than d6 with Hope/NL" first-pass impression
  was an artifact of the recipe choice.
- **Grad-accum=4 SFT runs cleanly on M2 at d8** with
  `--grad-checkpoint + compile`. No OOM, no NaN, smooth descent.
  Heavier paging than single-accum but well within bounds.
- **The `--grad-checkpoint` port from yesterday (commit `7e5f974`)
  holds up under 1500-microbatch SFT** without anomaly.

**Not answered:**

- **Does A2 beat d6_stage2 on canonical (`-x` unset) ChatCORE?**
  Today's `-x 100` puts the 0.012 gap to d6_stage2 within stderr.
  Canonical eval (~1.5 h wall) would settle whether the architectures
  are truly tied, A2 ahead, or A2 slightly behind. Worth running once
  if a clean comparison number is needed.
- **Would d8 base with Chinchilla-budget pretrain (~1.5 B tokens vs
  today's 82 M) lift the floor further?** Today's d8 base is
  sub-Chinchilla; SFT inherits that limitation. The natural extension
  is a longer d8 pretrain to test whether the SFT floor is base-quality
  bound or capacity bound at this scale.
- **What's the wall-clock floor for d8 SFT on M2?** Today's 2 h 41 min
  includes meaningful paging cost. A cleaner system (no Docker /
  server.py / faprox / browser) might hit ~2 h. Probably not worth
  optimizing further unless we plan to run many more d8 SFT variants.
